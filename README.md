# portfolio

Personal site for Sharique Zarar Rahman — work history, project write-ups and a
Markdown blog. Static output, served by nginx from a container.

Runs at **v2.zararsharique.com**, alongside the current site at
`zararsharique.com` on the same host. The reverse proxy that fronts
`zararsharique.com` gains one `server_name v2.zararsharique.com` route to this
container — see the "Deploying" section.

## Stack

- **Astro** — static output, no client framework
- **Content collections** — schema-validated work, project and blog entries
- **Fontsource** — Geist, Newsreader and JetBrains Mono, self-hosted
- **Phosphor icons** via `astro-icon`, inlined as SVG at build time
- **Docker + GitHub Actions + EC2** — image built in CI, pulled and restarted on the host

No CSS framework. The design tokens live in `src/styles/tokens.css` and nothing
else hardcodes a colour.

## Running it

Astro needs Node 18.20.8+, 20.3+ or 22+. Node 22 is what CI and the image use.

```bash
nvm use 22          # or 24
npm install
npm run dev         # http://localhost:4321
```

```bash
npm run build       # writes dist/
npm run preview     # serve dist/ locally
npm run check       # type-check components and validate content frontmatter
```

## Editing content

Everything on the page is data. None of it lives in markup.

| What                                                                  | Where                          |
| --------------------------------------------------------------------- | ------------------------------ |
| Name, tagline, socials, résumé link, availability badge, analytics ID | `src/site.config.ts`           |
| Work history                                                          | `src/content/work.json`        |
| Projects in the bento grid                                            | `src/content/projects.json`    |
| Blog posts                                                            | `src/content/blog/*.md`        |
| The stack grid                                                        | `src/components/Toolbox.astro` |
| Schemas for all three collections                                     | `src/content.config.ts`        |

A field that does not match its schema fails the build rather than rendering
blank, so `npm run check` catches typos before a deploy does.

### Two things to update

1. **Work dates.** Every entry in `work.json` has `"period": ""`, which hides
   the date range on the timeline. Fill them in (`"Jan 2025 — Apr 2025"`) and
   they appear.
2. **The seeded blog posts.** The three posts in `src/content/blog/` were
   drafted from the Notion write-ups as a starting point. Read them before
   publishing — they describe the work in the first person.

### Adding a post

```markdown
---
title: A specific claim, not a topic
date: 2025-06-01
summary: One sentence. Shows on the index, in RSS and in link previews.
tags: ["Terraform", "AWS"]
accent: blue # red | blue | green | yellow — tints the tags
draft: false # drafts render in dev, never in a build
---
```

The filename becomes the URL: `src/content/blog/my-post.md` → `/blog/my-post`.

## Deploying

Push to `main`. CI type-checks and builds as a gate, then SSHes to the host,
which holds a git checkout at `/opt/apps/portfolio-v2`:

```bash
git fetch origin main && git reset --hard origin/main
docker compose up -d --build          # builds the image locally, recreates the container
```

No registry — the image is built on the host, not pushed anywhere. Pull requests
run the type-check and build without deploying.

Required repository secrets: `HOST`, `USERNAME`, `KEY` (the SSH target, login and
private key). No Docker Hub credentials are used.

### How it runs on the host

`zararsharique.com` is a Docker Compose project (`portfolio`) in
`/opt/apps/portfolio/`: an `nginx` container owns 80/443 and terminates TLS, and
reverse-proxies to a content container over the project's default network.

This site is a **second content container** joined to that same network:

- `docker-compose.yaml` here defines only `my-portfolio-v2` (no published
  ports), attached to the external network `portfolio_default`.
- The proxy's `/opt/apps/portfolio/nginx.conf` gets one
  `server_name v2.zararsharique.com` block that `proxy_pass`es to
  `http://my-portfolio-v2:80/`. See `deploy/proxy-v2.zararsharique.com.conf`.
- TLS for the subdomain is a Let's Encrypt cert issued with the existing
  `certbot` service (webroot), living next to the `zararsharique.com` cert.

One-time host setup: add `deploy` to the `docker` group;
`git clone https://github.com/sharqX/portfolio_v2.git /opt/apps/portfolio-v2`
(owned by `deploy`); add the proxy server block; issue the cert. Nothing about
the running `zararsharique.com` site changes.

### Rolling back

On the host, check out the good commit and rebuild:

```bash
cd /opt/apps/portfolio-v2
git reset --hard <commit-sha>
docker compose up -d --build
```

The next push to `main` moves the host back to the tip of `main`.

## Theming

Light and dark, driven entirely by tokens — no component knows which theme is
active.

- **Default is the system setting.** With nothing stored, `<html>` carries no
  `data-theme` and the `prefers-color-scheme` blocks in `tokens.css` decide.
  The page keeps following the system if it changes mid-session.
- **The nav toggle sets an explicit choice**, stored in `localStorage` under
  `theme` and applied as `data-theme="light"` or `"dark"`. An explicit choice
  beats the system in both directions.
- **No flash.** An inline script in `<head>` (in `Base.astro`) applies the
  stored attribute before the stylesheets load.
- **No JavaScript, no toggle.** The button ships `hidden` and is revealed by
  `src/scripts/theme.ts`, so it is never a dead control. The system theme still
  applies.

Dark is a warm charcoal (`#191918`), not black, with off-white ink and the four
pastels rebuilt as low-luminance tints. To change either palette, edit the three
blocks in `src/styles/tokens.css` — `:root`, the `prefers-color-scheme: dark`
block, and `:root[data-theme='dark']`. The last two carry identical values; both
are needed so the toggle can override the system in either direction.

Code blocks use Shiki's dual-theme output (`github-light` / `github-dark`, set in
`astro.config.mjs`). Light values are inline, dark values are CSS variables
activated by the `.astro-code` rules in `prose.css`.

### Contrast

Measured against WCAG AA (4.5:1 for normal text). Everything passes except one
value, which comes from the design spec:

|                        | Light      | Dark      |
| ---------------------- | ---------- | --------- |
| Body ink on canvas     | 18.2:1     | 14.9:1    |
| Muted text on canvas   | **4.32:1** | 6.24:1    |
| Muted text on cards    | **4.48:1** | 5.72:1    |
| Tag text on its pastel | 4.6–6.3:1  | 7.5–8.8:1 |

Light-mode `--ink-muted: #787774` lands just under AA for normal-size text.
It is used for section ledes, card summaries and meta lines. Changing it to
`#6b6a66` gives 5.2:1 and is a one-line edit in `tokens.css`; it is left at the
spec value until you decide.

## Design constraints

Deliberate, and worth keeping if you edit the CSS:

- Body text is `#111111`, never pure black. Secondary text is `#787774`.
- Every card, divider and border is exactly `1px solid #EAEAEA`.
- Colour appears only in tag pills and inline code, only as the four muted
  pastels defined in `tokens.css`.
- Radii stop at 12px. Pills are for tags, never for buttons or cards.
- Shadows are `0 2px 8px rgba(0,0,0,0.04)` on hover and nothing at rest.
- Motion animates `transform` and `opacity` only, and stops entirely under
  `prefers-reduced-motion: reduce` — including the theme crossfade.
- Both themes are defined only in `tokens.css`. If you find yourself writing a
  hex value in a component, add a token instead, or it will be wrong in one of
  the two themes.
